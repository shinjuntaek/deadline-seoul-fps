# 서울 탈출 캠페인

복원된 25c29bf 버전을 기준으로 추가한 이동형 모드입니다. 기존 5웨이브 방어전과 좀비 사진 기반 표현, 총기, 저장 설정은 유지합니다. 엔진은 Three.js 0.164.1입니다.

## 플레이

메뉴의 **서울 탈출 캠페인**을 선택합니다. WASD/모바일 이동 패드, 마우스/터치 조준, 클릭/발사 버튼, R/재장전 버튼은 기존과 같습니다.

| 구역 | 이동 경로 | 전투 | 완료 조건 |
|---|---|---|---|
| 1 | 서울역 뒤편 상가 골목 | 워커 12, 러너 3 | 감염체 정리 → 초록색 출구 구역 3초 집결 → 문 통과 |
| 2 | 청파 지하차도 | 워커 15, 러너 7 | 감염체 정리 → 출구 3초 집결 → 강변으로 이동 |
| 3 | 한강 임시 대피소 | 워커 19, 러너 10, 브루트 1 | 감염체 정리 → 마지막 출구 8초 집결 → 탈출 성공 |

시작점부터 최종 집결 지점까지 직선 이동 약 330m, 맵 전체 길이 약 350m의 연결된 1차 경로입니다. 로딩/순간이동으로 같은 방을 재사용하지 않습니다. 상가·셔터·창틀, 지하차도 천장/기둥/유도등, 강변 난간/수면/대피 차량이 구역을 구분합니다. 본격적인 분기형 캠페인이나 원작 수준의 맵 세트는 아닙니다.

전투는 구역 안으로 이동하면 시작합니다. 진행 중 다음 봉쇄문을 우회할 수 없습니다. 협동에서는 서버가 모든 연결된 생존자의 집결과 통과를 확인합니다. 다음 구역 진입 시 체력 최대 +35, 방탄 최대 +25, 소총 예비탄 최소 180/산탄 최소 40을 보급합니다. 이번 구현은 구역 간 보급이며 영구 체크포인트 저장/이어하기 기능은 아닙니다.

협동 방 생성 화면의 **방 작전 → 서울 탈출 캠페인**을 선택합니다. 참가자는 방장의 모드를 자동으로 따릅니다. 원래 방어전도 별도로 선택할 수 있습니다.

## 구현 경계

- `shared/campaign.mjs`: 클라이언트/서버 공통 이동 범위, 차량 충돌, 닫힌 문, 구역 전투/집결/진행 계약.
- `client/campaign.js`: 공유 재질/geometry와 InstancedMesh를 사용하는 환경 청크, 원래 게임과의 전환, HUD/출구/보급.
- `multiplayer/coop-engine.mjs`: 협동 캠페인의 적 생성, 확장된 이동 범위, 팀 집결, 보급, 승리 스냅샷.
- `scripts/campaign-upgrade.cjs`: 기존 복구 빌드 후 캠페인 코드를 연결. `dist`만 수동 수정하지 않습니다.
- 맵은 세션당 한 번 생성해서 재사용합니다. 112m(소프트웨어 GPU 74m) 밖의 환경 청크를 숨기고, 고정 조명은 저사양 2개/그 외 4개 이내, 소프트웨어 GPU에서는 비활성화합니다. 원래 적 동시 생성/시체 정리 제한을 사용합니다.
- 원래 좀비·무기·오디오·에셋의 출처를 유지하며 새 외부 에셋, 유료 생성, 추가 플러그인은 사용하지 않았습니다.

## 검증과 남은 제약

`npm run build`에 기존 서버 검사와 캠페인 진행/충돌/재접속 테스트가 포함됩니다. `scripts/browser-campaign.cjs`는 실제 Chromium 입력과 전투, 모바일 터치 에뮬레이션, 두 브라우저 협동 방을 검증합니다. `?campaignQA=1`의 위치/적 제거 보조 기능은 localhost/127.0.0.1에서만 노출됩니다. 공개 Preview에는 노출되지 않습니다.

구역 전체 진행 검증에는 테스트용 위치 배치/적 제거가 사용됩니다. 자연 플레이로 모든 적을 처치한 완주나 난이도 검증으로 간주하지 않습니다. Chromium에서 실제 사격으로 이동하는 적을 처치하는 항목은 별도로 실행합니다. 테스트 결과와 측정치는 GitHub Actions의 `seoul-campaign-evidence`에 보관합니다.

실제 PC/모바일 GPU, 15분 이상 무보조 플레이, 외부 친구 서버의 장시간 안정성은 이 캠페인 변경으로 검증되었다고 주장하지 않습니다. 공개 Vercel 협동 API의 방은 프로세스 메모리에 있으므로 인스턴스가 달라지거나 재시작되면 참가/재접속이 실패할 수 있습니다. 캠페인 동기화 테스트 통과와 공개 방의 지속성은 별개입니다.

운영 주소 변경이나 기존 PR 병합 없이 별도 Preview와 Draft PR #7로 검토합니다.
